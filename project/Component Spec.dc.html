Corporate Specialties · The Swag Desk

Content Hub — Component Spec

Build spec for the Astro front end and the Sanity schema behind it. Field names in this document are the Sanity field names. Visual values are token references only — the token table in §1 is the single source of truth for every hex, size, and space.

Version 1.0 · Aug 2026 Companion prototype: Swag Content Hub.dc.html Stack: Astro + Sanity

How to read this

Data lists every Sanity field a component consumes, marked (req) or (opt), followed by what renders when an optional field is absent. Fields marked derived are computed at build time, not authored.

Responsive is stated per component, at the named breakpoints in §1.4. Where a component behaves differently on two pages, both are named.

Tokens appear as --token-name. A raw value inside a component entry is always tagged exception with a reason.

placeholder marks invented copy, stand-in imagery, or a section that exists to prove the layout. Full inventory in §6. Decisions I had to make are logged in §7.

3 · Page components

Every card treatment in the prototype is one component with a variant prop. Where I merged things that were specced separately, the merge is noted.

3.1 Post card

PostCard · variant: featured | standard | compact
Merged
Previously three separate treatments (large featured / standard with image / compact text-only). Now one component; variant is the only prop that differs. The post-page “related” card and the index feed card are the same standard variant — do not build a RelatedCard.
Data
title (req), slug (req), category.title + category.slug (req), publishedAt (req), heroImage (opt, with alt), excerpt (opt), author.name (opt at card level), readTime (opt), variant (req, default standard).
Absent heroImage: render the fallback tile — --surface-accent field at the same ratio, “CS” monogram in Playfair at --border-accent, no icon, no text label in production (the “No image · fallback” caption in the prototype is a spec annotation, not content). Never substitute a stock photo.
Absent excerpt: omit the line; do not fall back to a body-text slice. Absent readTime: meta line renders date only, no separator. Absent author: meta line renders date · readTime.

Long titles
Cards must hold a three-line headline without changing height relative to siblings. standard reserves 3 lines via min-height so a one-line and a three-line card align in the same row; overflow past 3 lines is clamped with an ellipsis. Titles never hyphenate; text-wrap: pretty. Test string: “17 Corporate Gift Ideas Your Remote Team Will Actually Use”.
Photo tolerance
Image sits in a --surface-sunken well at a fixed ratio with object-fit: cover; object-position: center. No rounding, no border, no overlay gradient — a white-background product shot and a dark lifestyle shot both read as intentional against the warm well. Sanity hotspot/crop respected for the 3/2 crop.
Responsive
mobile: full width, 1-up; featured title floors at 23px; image ratio unchanged. tablet: 2-up; compact variant switches from 3-across to 2-across. desktop / wide: 3-up, ratio and clamps unchanged. Card internals never reflow — only the grid does.
States
Hover (whole card is one link): title → --accent, image scales 1.02 inside the fixed well over --dur; nothing lifts or shadows. Focus-visible: 2px --accent outline, 2px offset, on the card bounding box — not on the title alone. Visited: no change. Active: title --accent-hover. Touch: no hover transform.
A11y
One anchor wrapping title; card surface uses a stretched-link pseudo-element so the category label can stay a separate link to the archive. Image alt from heroImage.alt; fallback tile is aria-hidden.

3.2 Chip

Chip · kind: category | tag · style: bare | framed | pill
Merged
Category chip and tag chip were specced separately; they are one component. kind sets semantics and link target, style sets the shell.
Data
title (req), slug (req), kind (req), style (opt — defaults: category→bare inside cards, framed in article headers; tag→pill), isActive (opt bool, tags only), count (opt int, shown only in the archive filter row).
Styles
bare: --type-label in --brand-green, no shell. framed: same type, --surface-accent-soft fill, 1px --border-accent, --radius-1, padding --space-2 / 11px exception 11px is an optical inset for mono caps. pill: --radius-pill, 1px --border-strong, text --text-muted; active = --text-primary fill, --text-on-inverse label, no border.
Responsive
Unchanged across breakpoints. In a filter row: mobile/tablet the row scrolls horizontally with scrollbar hidden, edge-to-edge to the gutter, no wrapping and no “more” affordance; desktop+ it wraps to two lines maximum. Hit area is 36px tall visually, padded to 44px on touch.
States
Hover: bare → --accent text; framed → border --accent; pill → border and text --accent. Focus-visible: standard ring. Active tag: as above, plus an “×” glyph appended to clear that filter. Disabled (tag with zero matches after other filters): --text-subtle, border --border-hairline, not focusable.

3.3 Post grid & feed states

PostGrid · state: ready | loading | empty
Data
posts (req array — may be empty), label (opt eyebrow, e.g. “Latest”, “Page 2”), rangeLabel (opt, e.g. “7–12 of 42”), cardVariant (opt, default standard), state (req).
Loading
Skeleton mirrors the standard card exactly: --surface-sunken block at 3/2, then a 10px-tall bar at 40% width (category), two 14px bars at 100%/70% (title), one 10px bar at 30% (meta) — all --surface-sunken, --radius-0. Opacity pulses 1 → 0.55 → 1 over 1.4s, prefers-reduced-motion holds it static at 0.7. Render exactly one screenful (6 on desktop, 3 on mobile). Astro ships static HTML, so this state only appears on client-side filter/pagination fetches; if pagination stays as full page loads, skeletons are never needed — call made: spec it, build it only when filtering goes client-side.
Empty
See 3.6. The grid renders nothing itself — it delegates to EmptyState so the message can name the active filters.

3.4 Pagination

Pagination · real numbered links, no infinite scroll
Data
currentPage (req), totalPages (req), basePath (req — e.g. /blog/gifting-guides), pageSize (req, 6 on archives / 6 + 3 compact on the index). URLs are {basePath}/page/{n}, page 1 canonical at {basePath}. Emit rel prev/next.
Page 1
“← Prev” renders as text in --text-subtle, not a link, aria-disabled, no border. Current page: --text-primary fill, inverse label, aria-current="page".
Page 2+
“← Prev” becomes a live link in --text-primary with a 2px --accent bottom rule (same treatment as Next). Numbered links are 1px --border boxes; the feed eyebrow changes from “Latest” to “Page {n}” and the range label to “{from}–{to} of {total}”. Window: first, last, current ±1, ellipsis elsewhere (never a link). On the last page “Next →” disables the same way Prev does on page 1.
Responsive
mobile: Prev / “Page 2 of 7” / Next only — numbered links hide below 600px (they are the first thing to break the row). tablet+: full numbered set, centered. Targets 44px tall at every width.
States
Hover on a numbered link: border → --accent, text → --accent. Focus-visible: standard ring. Current page and disabled arrows have no hover.

3.5 Category header

CategoryHeader
Data
category.title (req), category.description (req), postCount (req, derived), breadcrumb (derived). No image, ever — the sage field is the identity. Absent description should be prevented by validation; if missing, the title block still renders and the count moves up into the left column.
Layout
--surface-accent band, full bleed, bottom 1px --border-accent. Two columns, baseline-aligned: text left (description capped 56ch), count right as --type-serif-lg numeral in --brand-green over a --type-meta caption. On page 2+ the header is unchanged (it is not a page-specific element).
Responsive
mobile/tablet: single column, count drops below the description and sits inline (numeral + caption on one line). desktop+: two columns, count right-aligned. Vertical padding follows --section-y.

3.6 Empty state

EmptyState · context: filteredArchive | emptyCategory | search
Data
activeFilters (opt array of tag titles — echoed verbatim in the headline), categoryTitle (req in archive contexts), categoryCount (req), clearHref (req), strategistHref (req).
Content
Bordered block (1px --border, no fill), left-aligned, max 62ch: Playfair “CS” monogram in --border-accent, --type-h2 headline naming the filters, one paragraph offering three exits, then two actions: “Clear filters” (primary, ink fill) and “Talk to a strategist” (secondary, 1px border). Never an illustration, never centered.
emptyCategory (a live category with zero published posts): same shell, headline “Nothing published in {category} yet”, and the secondary action becomes “Browse all stories”. This case should be prevented editorially — a category with no posts should not appear in the nav.
Responsive
mobile: padding drops to --space-6, buttons stack full-width. tablet+: buttons sit inline. Filter row and pagination both remain visible above/below; the empty state replaces the grid only.

3.7 Article header

ArticleHeader + HeroFigure
Data
category (req, framed chip), title (req), dek (req), author.name + author.role + author.avatar (name req, role opt, avatar opt), publishedAt (req), readTime (opt), reviewedBy (opt), heroImage + alt + caption + credit (all opt).
Absent avatar: render a 46px --surface-accent circle with the author's initials in --brand-green. Absent heroImage: skip the figure entirely — do not substitute the fallback tile at hero scale; the header's white space carries it. Absent caption: no caption row, no rule. Absent readTime/reviewedBy: those meta items disappear; separators are gaps, not glyphs, so nothing dangles.
Layout
Title capped at 44ch for a 2–3 line ragged block (not centered); dek at 52ch; meta row divided from the dek by a 1px --border rule. Hero figure is full-bleed at --ratio-hero; caption sits back inside the container with a 2px --accent flag (inline images use --border-accent — the accent flag is reserved for the hero).
Responsive
mobile: title floors at 32px; hero ratio relaxes to 3/2 (21/9 is unreadable at 390px) with a 200px min-height; meta row wraps to two lines. tablet: hero 16/9. desktop+: hero 21/9, meta on one line.

3.8 Table of contents

TableOfContents · mode: sidebar | bar
Data
headings (req, derived from body at build: array of level 2|3, text, slug). Slugs are generated from heading text and written back onto the rendered heading ids — the CMS never authors them. Renders only when there are ≥4 H2s; below that, no TOC and no empty shell. H4+ is ignored.
Desktop
sidebar: 210–260px column left of the prose, position: sticky; top: 74px (clears the sticky category nav), align-self: start. Rows are H2s at --type-card-sm with a 2px left rule (--border-hairline at rest, --accent + weight 700 when active); H3s indent 24px at 13px. Active section tracked with IntersectionObserver (rootMargin −40% 0 −55%), one active at a time, no scroll-spy jitter. Below it: a Share group. Anchor click updates the hash and scrolls with scroll-margin-top: 90px on headings.
Mobile
Answered explicitly: bar mode — a collapsed sticky bar at the top of the article, not a bottom sheet and not hidden. It reads “Contents · {n} sections” on --surface-sunken with a +/− glyph, sticks at top: 52px under the category nav, and expands in place into a full-width list (44px rows, H3s indented). It auto-collapses on anchor selection. A 2px reading-progress rule sits under the bar, filling in --accent as the article scrolls; it is the only progress indicator on the site. The expanded list is aria-expanded-controlled from the bar button.
Responsive
< 900px: bar. ≥ 900px: sidebar, and the progress rule is dropped (the sidebar's active state does that job). Markup is shared; only the shell swaps, so headings and slugs exist once. Anchors are real <a href="#slug"> links in both modes — crawlable, and marked up as SiteNavigationElement (name + url per item).

3.9 Author bio · Related posts · Guides module

AuthorBio · RelatedPosts · GuidesModule
AuthorBio
Data: author.name (req), avatar (opt → initials circle at 72px), role (opt), bio (opt — if absent the whole block is omitted, no “no bio yet”), links (opt array), postCount (opt, derived, renders as “All {n} articles”). Layout: top 1px --border rule inside the prose measure, avatar left, text at 58ch. Responsive: avatar and text stay side by side at every width (72px + flex) — it wraps only under 320px. States: links use the standard text-link treatment.
RelatedPosts
Data: posts (req, exactly 3 — same category first, then shared tags, then recency; never the current post), eyebrow (opt, default “Keep reading”). Renders standard PostCards. If fewer than 3 exist: render what exists (2 cards in a 2-col grid); if 0, omit the section. Responsive: 1 / 2 / 3 up. Title token drops to 18.5px here exception so a related card never out-shouts the article it follows.
GuidesModule
Data: guides (req, 4 posts where isGuide, ordered by updatedAt), heading (req), blurb (req), allHref + allCount (req). Numbered rows (01–04) with title + “Updated {month} · {readTime}”. Layout: --surface-inverse band, two columns: pitch left, list right, rows divided by 1px #3C5138 exception inverse-surface rule; add as --border-on-inverse if a second inverse block appears. Deliberately image-free so it reads as a reference shelf, not a feed. Responsive: stacks to one column below 900px, pitch first. States: row hover → title --accent; focus ring uses --text-on-inverse for contrast on the dark field.

3.10 CTA block & newsletter

CtaBlock · placement: inlineFeed | endOfArticle  ·  NewsletterSignup · placement: inline | footer
Merged
The in-feed conversion module and the end-of-article CTA are one component with a placement prop: inlineFeed is sage with an email capture, endOfArticle is inverse with two buttons. Same fields, same copy slots. Newsletter inline/footer likewise.
Data
CtaBlock: eyebrow (opt), heading (req, serif), body (req, ≤44ch), primaryLabel + primaryHref (req), secondaryLabel + secondaryHref (opt — omit and the primary sits alone), captureEmail (opt bool, inlineFeed only), reassurance (opt, the small line under the field). Primary action for the whole hub is “Talk to a strategist”. NewsletterSignup: heading (req), body (opt), placeholder (opt, default “Work email”), submitLabel (opt, default “Subscribe”), proofLine (opt, e.g. subscriber count), listId (req, ESP list).
Placement
inlineFeed sits after the first row of feed cards (index) — one per page, never two — spans the full grid width, and carries no border so it reads as an editorial aside rather than an ad slot. endOfArticle is full-bleed inverse between the FAQ and Related. Newsletter inline is available as a body block for posts that warrant it; footer renders on every page.
Responsive
mobile: single column, field and button stack full-width (button 48px tall), reassurance line below. tablet+: two columns — copy left, form/actions right, vertically centered; field and button sit on one row with the button at white-space: nowrap.
Form states
Rest: 1px border (--border-strong on light, #B9C7AE on sage, --border-inverse on dark). Focus: border --accent + standard ring. Invalid: border --accent-hover, message below in --type-meta, never a toast. Submitting: button label → “Sending…”, disabled, opacity .7. Success: the form is replaced in place by a mono confirmation line (“Check your inbox — the PDF is on its way.”) inside the same block; no modal, no redirect. Error: same slot, message plus a retry link.

4 · Article body blocks

These are insertable blocks in the Portable Text array, each one a Sanity object schema an editor picks from the insert menu — not styling applied to article content. §4.1 covers the default prose marks (the things editors get without inserting anything); §4.2 onward are the blocks.

Shared spacing law (--block-y = 34px mobile / 38px desktop): every block takes --block-y above and below against a paragraph. Two adjacent blocks collapse to 26px. A block immediately after an H2 or H3 uses 20px (the heading already opened space). A block never sits directly against another block's caption without the collapse rule applying. All blocks stay inside --measure except where noted.

4.1 Prose defaults

Portable Text styles & marks — not insertable blocks
Allowed
Styles: normal, h2, h3, blockquote. Lists: bullet, number. Marks: strong, em, link, code. No h1 (the page owns it), no h4+, no underline, no text color, no font-size overrides, no centered text.
Rhythm
Paragraph: --type-body, --text-body, 26px below, text-wrap: pretty. H2: 46px above / 14px below. H3: 30px above / 12px below. Heading-to-paragraph space is always tighter than heading-to-preceding-block — the heading belongs to what follows. Lists: 22–24px indent, 10px between items, 30px below the list, markers outside the measure. Blockquote as a style is reserved — editors get the pullQuote block instead (4.2), so the mark exists only for imported content.
Drop cap
First paragraph of a post only: Playfair initial, 3.6em, --accent, floated with 12px right / 6px top offset. Suppressed if the first block is not a paragraph, and on screens under 400px.
Responsive
Measure is min(--measure, 100%); body floors at 16.5px and heading spacing scales down ~20% below 600px (H2 46→34px above). Line height never drops below 1.7 at any width. Links inside prose: --accent with a 1px underline at 0.15em offset; hover --accent-hover with a 2px underline.

4.2 Pull quote

pullQuote
Data
quote (req, ≤220 chars — validate; longer defeats the type size), attribution (opt), attributionDetail (opt — role, company size). Absent attribution: the footer line and its space are omitted; quote alone is valid.
Render
--type-quote in --text-primary, 3px --accent left rule, 26px inset, no quotation-mark graphic (typographic quotes in the text only), attribution in --type-meta. It is not a <blockquote> of body copy — it is a display element, and the same words should not also appear in the running text.
Mobile
Inset drops to 18px, size to 21px; rule stays 3px. Block spacing 34px.

4.3 Inline image & two-up pair

inlineImage · imagePair
Data
inlineImage: image (req, with alt req), caption (opt), credit (opt), width (opt: measure default | wide = breaks 120px past the measure on each side, desktop only), ratio (opt: 3/2 default | 4/5 | 1/1).
imagePair: images (req, exactly 2, each with alt), captions (opt per image), ratio (opt, default 4/5 — shared, both crops identical).
Absent caption: no caption row and no rule; the image's bottom margin does not change. An image block with no alt fails validation — this is the one hard block.
Render
Image in a --surface-sunken well at a fixed ratio, object-fit: cover, --radius-0. Caption 10px below in --type-caption / --text-subtle, preceded by a 2px --border-accent vertical flag so it can't be misread as body copy. Credit appends to the caption in the same style after an em dash. Pair uses a 14px gap and equal columns.
Mobile
wide collapses to measure (no bleed under 900px). imagePair stays two-up down to 390px — the 4/5 crop at ~170px wide still reads, and stacking it would break the comparison the pair exists to make. Captions stay under their own image. Below 340px it stacks.

4.4 Product spotlight

productSpotlight
Data
product (req, ref → product) or inline overrides of: name (req), oneLiner (req), image (opt + alt), priceLow/priceHigh (opt pair), minQty (opt), ctaLabel (opt, default “Request pricing”), ctaHref (req — quote form with the SKU prefilled, not the product page, unless product.slug is set and the editor picks “View product”).
Absent image: the media column collapses and the block becomes text-only full width with the eyebrow, name, one-liner, price and CTA — not the CS monogram tile (that is a card-only device). Absent price pair: the price line is omitted entirely; never render “Price on request” (the CTA says that). Absent minQty: drop the “/ n pc min” suffix.
Render
1px --border on --surface-raised, two columns: square image well (--ratio-product, --surface-sunken, divided by a 1px border) and a text column. Eyebrow “Product spotlight” in --accent — the only orange eyebrow in the body, which is what marks the block as commercial without a badge. Price in mono; CTA is the ink-filled small button. Marked up as Product + AggregateOffer (lowPrice, highPrice, priceCurrency USD).
Photography tolerance: the square well plus a warm tint means a white-cutout shot and a shot with a grey studio background both sit consistently; never apply a drop shadow or background removal.
Mobile
Stacks: image on top at 1/1 (full block width), text below, CTA full-width at 48px. Max two spotlights per article — enforce in validation, not layout.

4.5 Comparison table

comparisonTable
Data
label (opt eyebrow, e.g. “Compare · best drinkware for remote kits”), columns (req, 3–5 header strings — validate the max; 6 columns cannot be read on mobile), rows (req, array of cells; first cell is the row label), footnote (opt — sourcing and date, strongly encouraged), highlightRow (opt index → --surface-accent-soft fill for an editor's pick).
Absent footnote: nothing renders; no “Source: —”. Ragged rows (a row with fewer cells than columns) render empty cells rather than shifting.
Render
Real <table> with <thead> and scope="col", wrapped in a 1px --border frame. Header row --surface-sunken with mono uppercase labels; body rows 14px, zebra on --surface-raised, row label weight 700 in --text-primary, 14px cell padding, hairline row rules. Footnote below in --type-caption. Schema type Table.
Mobile
Horizontal scroll inside the frame, min-width 460px, scrollbar hidden, first column not frozen (a frozen column at 390px leaves 120px of data). The frame edge is the scroll affordance; add aria-label and tabindex="0" on the scroller so it is keyboard-reachable. Does not transform into stacked cards — call made: card-per-row loses the comparison, which is the block's only purpose.

4.6 Callout

callout · tone: tip | caution
Data
tone (req: tip | caution), label (opt — defaults “Tip” / “Watch out”), body (req, rich text: paragraphs, lists and links allowed; no nested blocks). Absent label: the default is used; an empty string suppresses the label row entirely.
Render
tip: --surface-accent-soft field, 2px top rule in --brand-green, label in --brand-green. caution: --surface-warn field, 2px top rule and label in --accent / --accent-hover. Both: no icon, no left border, no rounding; body at --type-body-sm capped at --measure-narrow. The top rule is the tone signal — colour alone never carries it (non-colour cue = the label text).
Mobile
Padding 18px, full measure width, block spacing 32px. Never side-by-side with text.

4.7 Downloadable resource

Data

Mobile

4.8 FAQ

faqBlock · display: open | accordion
Data

Also available as post.faq at document level, which renders in the same component between the article body and the end CTA — one FAQ per page maximum, so if both exist the body block wins and the document field is ignored (validate).
Render
Eyebrow + rule, then items divided by 1px --border rules (first item has a top rule, last a bottom rule). No cards, no chevrons in open mode. accordion adds a +/− glyph in --accent and a button-wrapped question row; answers stay in the DOM (height animation, hidden not conditional render) so FAQPage markup always validates. Mobile
Same single column at every width; question floors at 17px, item padding 18px. accordion rows are 44px minimum with the whole row as the target. Recommend open for ≤4 items at any width.

7 · Calls I made

Ambiguities I resolved rather than leaving open. Each is a decision you can reverse cheaply.

Mobile TOC is a collapsed sticky bar, not a bottom sheet.A bottom sheet competes with the reading position and needs a scrim; the bar keeps the article in view and doubles as the progress indicator. Reversible: only the shell changes, headings and slugs are shared.
Comparison tables scroll horizontally on mobile instead of restacking.Stacked card-per-row destroys the comparison. Cost: a horizontal scroll gesture inside vertical content, mitigated by the visible frame edge and a keyboard-reachable scroller.
The image pair stays two-up to 390px.Same reasoning: the block exists to hold two things side by side. Stacking is available under 340px only.
Numbered pagination hides below 600px.Prev / “Page n of m” / Next only. The numbered links remain in the HTML for crawlers via rel prev/next; they are visually hidden, not removed.
One category per post; tags are cross-category.The brief needed every card to carry one unambiguous category label, which multi-category posts make impossible. Archive filter rows therefore show tags, not sub-categories.
Feed grids stay auto-fit, and the named breakpoints describe outcomes.Container-driven columns survive being embedded anywhere (sidebar, narrow template) without new media queries. The breakpoint table exists for the four discrete jumps that genuinely need one: TOC mode, hero split, pagination, nav overflow.
The featured card variant never appears on a category archive.The brief asked for “the same card grid, no hero treatment”. Featured is reserved for the index. If you later want a lead item on archives, use it there rather than inventing a fourth variant.
Skeletons are specced but conditional.Astro's static output means paginating and filtering by URL never shows a loading state. Build the skeleton only if filtering becomes client-side; otherwise it is dead code.
Article hero relaxes from 21:9 to 3:2 on mobile.A 21:9 crop at 390px is a 167px-tall strip. Editors should upload at 21:9 or wider and rely on the hotspot for the mobile crop.
No article-level “gated download” interstitial or exit modal.Gating lives in the resource block only, email-only, inline. Nothing on this hub interrupts a reader.
Open questions for you, not decisions I made:(a) per-category accent colours — currently every category label is --brand-green; (b) whether the Guides module needs its own landing page at /guides; (c) whether author pages exist (the bio links assume they do); (d) ESP for the newsletter and gated downloads, which determines the form-submission path in 3.10.
